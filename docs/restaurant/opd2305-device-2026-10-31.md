XLSX/PDF save buttons were observed and handled by the helper.

## Performance observations and limits

First Android activity launch reported 2,303 ms total / 2,309 ms wait; the separate web `restaurant:ready` mark was 3,316.9 ms including photo initialization. After force-stop, activity launch was 1,547 ms total / 1,571 ms wait and the web readiness mark was 2,652.3 ms with zero bundled-photo fetches. These are different timing windows, not values to add together or cashier-ready measurements; owner sign-in was separate.

Ten add/quote/remove cycles completed at approximately 171.6–194.5 ms, median 178.95 ms, including the existing 150 ms UI debounce. No long tasks were observed in that short probe. This is not pure CPU time, a sustained benchmark or a comparison with earlier phones.

Main-process PSS snapshots were about 193 MiB on first start, 240 MiB before the smoke checks, 368 MiB after billing/backups, and 198 MiB during later idle before any trim signal. One `RUNNING_LOW` trim signal was delivered without a crash or lost images/data. The post-trim screen and user activity differed, so no controlled reclaimed-memory amount is claimed. Final PSS after the separate restarted process and exports was recorded in `memory-final.txt`. These snapshots exclude separately hosted WebView renderer memory and do not establish a combined peak, absence of leaks or TVS memory acceptance. The transient earlier growth was mainly Graphics; it had already fallen during idle.

Wi-Fi setting was 0, mobile-data setting 1 and active default network was none. No network setting was changed in this session. Internet-independent startup, billing, backup and export were exercised; there was no need to toggle network settings for these checks.
